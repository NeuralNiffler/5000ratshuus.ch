# Stack-Entscheid Phase 1a

**Datum:** 2026-09-16
**Kontext:** Abschnitt 14, Schritt 2 des Entwicklungsdokuments (Stack-Vorschlag
innerhalb der Architekturrichtung aus Abschnitt 12), von Robin bestätigt.

Ausführliche Begründung und Nachteile stehen in der Session, in der der
Vorschlag gemacht wurde (Rückfragen- und Stack-Nachricht vom 2026-09-16).
Diese Datei hält nur die **Entscheide** fest, damit sie im Repository
nachvollziehbar bleiben.

| Baustein | Entscheid | Verworfen |
|---|---|---|
| Static Site Generator | Astro, statischer Output | Eleventy, Hugo |
| Sprache | TypeScript auf Node LTS | Python-Pipeline neben JS-Site |
| Artikelformat | Ordner pro Ausgabe: `artikel.md` + `geschaefte.json` | HTML pro Artikel, MDX |
| Build-Index | SQLite via `better-sqlite3`, bei jedem Build neu | `node:sqlite` (noch nicht stabil genug) |
| Hosting (noch nicht eingerichtet) | Cloudflare (Workers Static Assets) | GitHub Pages, Netlify |
| Kontaktformular | Eigener Cloudflare Worker mit `send_email`-Binding | Formspree, Web3Forms |
| Eingehende Mails (Phase 1c) | Cloudflare Email Routing + Email Worker | Postmark Inbound |

## Weitere Entscheide aus dem Rückfragen-Gespräch (2026-09-16)

- **Name/Domain:** `5000ratshuus.ch` als Favorit (zentral in
  [`src/site.config.ts`](../../src/site.config.ts), leicht änderbar, bis der
  Kauf/die Verfügbarkeit bestätigt ist).
- **Git-Hoster:** noch kein Remote-Repository eingerichtet.
- **Repository-Sichtbarkeit:** öffentlich (für Reichweite). Konsequenz für
  Phase 1c: Rohmails aus dem Newsletter-Eingang dürfen nicht unverändert
  versioniert werden, weil sie persönliche Abmeldelinks enthalten — vor dem
  Ablegen bereinigen oder in einen privaten Speicher (z. B. Cloudflare R2)
  auslagern. Wird bei Phase 1c entschieden.
- **Slugs:** siehe
  [`2026-09-16-slug-regel.md`](2026-09-16-slug-regel.md).
- **Autor:** siehe
  [`2026-09-16-kein-personenautor.md`](2026-09-16-kein-personenautor.md).
- **SQLite-Archiv nach Thema/Art:** in Phase 1a bereits eingebaut (nicht auf
  eine spätere Phase verschoben).
- **JSON-Feldnamen:** Deutsch, ASCII (`referendumspflichtig`, `urheber`,
  `sitzungsdatum`, …), passend zu Abschnitt 9 des Entwicklungsdokuments.
- **Kurztext pro Geschäft:** lebt in `geschaefte.json` (Feld `kurztext`),
  nicht im Markdown-Fliesstext von `artikel.md`. Grund: Bei einer Zuordnung
  über eine Kennung zwischen zwei Dateien reicht ein Tippfehler, damit ein
  Text beim falschen Geschäft landet oder verloren geht; im JSON direkt beim
  Geschäft gibt es diese Fehlerquelle nicht.
- **Referendumsfrist:** Die bisherige, strikte Regel aus dem
  Entwicklungsdokument bleibt unverändert in Kraft (kein Datum, nie) — eine
  ursprünglich erwogene Lockerung (Datum zulässig, wenn wörtlich aus der
  Quelle zitiert) wurde von Robin im selben Gespräch wieder verworfen.
